# Stage 2: Prototypes

Turn an idea from [`1-ideas/`](../1-ideas/) into a small, working proof of concept.

**What goes here:** a scrappy prototype — code, a script, a rough demo, whatever proves the idea *can actually work*. It should be demonstrated against a **fictionalized use case**: made-up sample data, a made-up scenario, anything that lets you show the concept working end-to-end without needing real production data or real system access.

This does not need to be polished, secure, well-tested, or production-ready. It needs to *work once, visibly, against a plausible example.* That's the whole bar.

**Who can contribute:** anyone who wants to build. You don't need permission from whoever wrote the idea — pick any idea in `1-ideas/` that interests you, including ones that already have a prototype (competing prototypes with different approaches are welcome).

**How to contribute:**
1. Read the idea you're building from carefully.
2. Copy [`TEMPLATE.md`](TEMPLATE.md) into a new file in this folder, named `prototype-<slug>.md` (matching the idea's slug — add a suffix like `-alt-approach` if you're the second prototype for the same idea).
3. Put your actual code/demo in a subfolder next to your write-up, e.g. `prototype-meeting-digest/`.
4. **Link to the specific idea file you built from, right at the top.** This is required — it's what keeps the chain traceable.
5. Open a Pull Request (see the [root README](../README.md)).

**Worked example:** [`example_prototype.md`](example_prototype.md), which builds on [`../1-ideas/example_idea.md`](../1-ideas/example_idea.md).

Once your prototype is here, anyone can pick it up and write a review of it in [`3-reviews/`](../3-reviews/).
