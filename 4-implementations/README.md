# Stage 4: Implementations

Build a refined version of a prototype, applying the recommendations from its [`3-reviews/`](../3-reviews/) entry.

**What goes here:** a more solid implementation — closer to production-quality than the Stage 2 prototype — that specifically addresses what the review flagged. Where practical, write it **as if it were being refactored into a larger, existing codebase** (e.g. structured as a module/plugin with a clear integration point, config instead of hardcoded values, etc.). That larger codebase does not need to actually exist anywhere for this exercise — describe the integration target you're imagining, even hypothetically.

**Who can contribute:** anyone, but this stage benefits from someone comfortable turning a critique into a concrete build. If that's you, and an idea has made it all the way here, that's a strong signal it's worth your time — multiple independent people already found it worth building and worth reviewing before you ever showed up.

**How to contribute:**
1. Read the review closely — your job is to apply its recommendations, not to start over.
2. Copy [`TEMPLATE.md`](TEMPLATE.md) into a new file in this folder, named `implementation-<slug>.md`.
3. **Link to the specific review you're building from, right at the top.**
4. Open a Pull Request (see the [root README](../README.md)).

**Worked example:** [`example_implementation.md`](example_implementation.md), applying [`../3-reviews/example_review.md`](../3-reviews/example_review.md).

This is the last stage of the pipeline — there's nowhere further for a chain to go from here within this repo. What happens with a Stage 4 implementation after this (proposing it for a real project, publishing it standalone, etc.) is up to whoever built it.
